# Sidecar setup and maintenance

1. Resolve the actual checkout location. If this skill is packaged with the source, its project root is two directories above this file. If installed separately, ask for the checkout/repository URL or locate the user's explicitly named checkout; do not assume an absolute path. Read the project's [README](../../README.md) and `config/panel.example.yml`. Preserve any existing ignored local config and SQLite data.
2. Check `ruby -v` and `bundle -v`. Ruby >= 3.2, Bundler 4 and native build tools are required; Ruby 4.0 was tested on macOS. Report missing prerequisites and use the user's existing toolchain. Do not install global software without authorization. Linux is supported by portable paths and lockfile variants but runtime verification must be reported separately.
3. Run `bin/setup` from the checkout. It installs only project-local gems, copies the Turbo asset and example configuration when absent, and prepares SQLite. Run `bin/start` to serve loopback `http://127.0.0.1:47391`; use `PORT=47392 bin/start` if the port belongs to another application. Never kill unrelated processes. Stopping Rails stops its background reader thread. Only install a login service if the user requests it.
4. Edit only ignored `config/panel.yml`. Use generic project ids, labels/colors, exact local project paths and explicit repo mappings. Keep the three sources independent. Automatic agent readers default off. Configure one source at a time and verify actual source data; never present fixtures as connected work.
5. For Claude, prefer a known existing summary producer. Otherwise run optional `bin/setup-sessions` with an existing Python >= 3.10; it installs the pinned SDK in a local virtual environment. Set explicit project `local_paths`, `sources.claude.python` and `automatic: true`; run `bin/sync-sessions`. The official SDK list/read APIs are scoped and bounded; title/excerpt are not an AI task summary, live agent state or proof of completion. Claude archive state is unknown unless a supported producer supplies it.
6. For Codex, configure an existing CLI `binary` and Python 3, then opt in. The short-lived stdio app-server uses only initialize, state-DB-only active/archive lists and metadata reads. It never starts/resumes sessions or model turns. Normal agent runtime SQLite/log writes can require sandbox escalation; try the supported approval tool with the exact reason before declaring a permanent blocker. Never read credentials or private undocumented stores, or bypass a non-escalatable denial.
7. For GitHub, `bin/sync-github` uses existing authenticated `gh` for read-only queries. Do not create credentials, request reviews, merge or publish. Do not add unrelated integrations or new OAuth/token access without an explicit request.
8. Run `bundle exec rails test` and `bundle exec rails zeitwerk:check`. If Node is available, run `node --test test/auto_refresh_test.js test/pwa_test.js test/question_suggestions_test.js test/todos_client_test.js` (Node is not an application dependency). Verify the live UI and grounded Needs-you counts, operational status/action/owner, collapsed unknown history, source-health failures and archive states, dirty-field preservation and revision updates. Background polling runs about every 60 seconds; visible pages check revisions every 10 seconds. It remains polling, not server push. Record macOS/Linux and visual/HTTP tests separately.
9. Report exact local location/URL, real vs unavailable integrations and remaining setup. Keep optional notifications disabled until the user explicitly enables them and grants permission. Do not install global hooks or this skill automatically. For explicitly requested login startup, inspect existing services and port use, stop only the identified Sidecar process, then run `PORT=47391 bin/service install`. Verify `bin/service status`, health, loopback binding and restart; document `bin/service uninstall`. Never overwrite a service or enable root services/lingering. Offer browser install from the exact active URL. PWA offline status must never cache private data or queue answers.

Stable source IDs and truthful observation times are required. Refresh must preserve manual overlays, snooze, dismiss, production confirmations and unsaved form drafts after blur, including async races. Only source-confirmed archived agent rows are hidden; old/idle/local-dismissed are different facts. Agent response finished and task completed remain separate. GitHub CI belongs to current HEAD; recommendations require review history. Merge, deploy, rake task run/not-applicable and effect verification are separate facts with evidence.

For private backups, stop the app and copy local SQLite/config/snapshots to a private destination. Share only audited source, generic example config and this skill. Never send external messages, run production commands, activate LLM calls or transmit private sessions to a new provider as part of setup/maintenance. Remote publication is a separate explicitly authorized task.

For explicitly requested question suggestions, use existing CLI logins: Claude first, one Codex fallback. Probe login status without exposing identity/tokens; do not create keys or log in automatically. Generate only after the user's button click and only for verified pending non-secret questions. Preserve context bounds, timeout/cancel/deduplication and provider provenance. Reject access/safety restrictions without fallback. Claude is configured without tools/customizations and requires its own successful CLI login check. Use only allowlisted runtime/login-location environment variables. Codex fallback is capability-blocked before any model call because complete tool removal is unverified; never enable it by weakening isolation. Explain cloud/subscription use and the gap. No suggestion approves permissions or sends a reply. External Desktop history does not provide an owning live reply connection. Verify with fake subprocesses; live provider execution is a separately reported user action.

## Todos maintenance

After a Todos update, rerun `bin/setup` to copy the locked Trix assets and migrate Action Text/Active Storage/Todos tables. Use the existing Rails gems; no npm, TypeScript, cloud provider or image-processing binary is needed. Verify custom and source-derived todos, project assignment, checklist saves, rich links/images, Complete/Reopen, and preservation after source archive/removal. Run `bundle exec rails test test/todos_test.rb` and optional `node --test test/todos_client_test.js` alongside the existing checks. The optional `test/todos_browser_test.js` must target an isolated checkout with automatic readers disabled; never create test todos or upload fixture images to a user's real database.

Image uploads are bounded PNG/JPEG/GIF/WebP files on local disk. Do not enable generic Active Storage routes, remote URL fetching, external analyzers, cloud storage or automatic purge without a separate request. Browser verification covers real Chrome Trix image clipboard events and uploads; OS keyboard paste and other browsers are not yet verified. Keep that distinction in reports.

For Todos private backups, preserve the entire `storage/` directory, including its hidden `.secret_key_base` and `attachments/`, together with the database. Do not replace the signing secret: existing embedded attachment references depend on it. All uploads, SQLite files, local secrets and test screenshots must stay excluded from source releases. Source references are durable snapshots; source refresh/archive/removal must never delete or complete a todo.
